# GSI 读局原理与「会不会被当外挂」

## GSI 是怎么实现的？

DoDoClaw 使用 Valve 官方支持的 **Game State Integration（GSI）**，**不是**读内存、不是注入、不是驱动级 hook。

```
┌─────────────┐   HTTP POST JSON    ┌──────────────────┐
│  Dota 2 客户端 │ ───────────────► │ DoDoClaw 本机服务  │
│  (官方 GSI)   │  127.0.0.1:3000   │  FastAPI 接收解析  │
└─────────────┘                    └──────────────────┘
        ▲
        │ 读取 cfg
        │
  gamestate_integration_dodoclaw.cfg
  放在 dota/cfg/gamestate_integration/
```

1. 用户安装一份 `.cfg` 到 Dota 配置目录（游戏启动时加载）。  
2. 对局中，**客户端主动**按 throttle/heartbeat 把当前状态 POST 到本机 URL。  
3. DoDoClaw 只做：**监听本机端口 → 解析 JSON → 给 LLM/提醒用**。

配置里开启的字段示例：地图时间、玩家经济、英雄血蓝、技能/物品、部分建筑与 draft 等。  
**不包含**完整视野外敌方坐标、完整小地图操作注入等「透视级」能力；GSI 暴露的是官方允许的有限状态快照。

相关代码：

- `config/gamestate_integration_dodoclaw.cfg` — 客户端推送配置  
- `src/dodoclaw/gsi/server.py` — 本机 HTTP 接收  
- `src/dodoclaw/gsi/state.py` — 归一化局势摘要  

## 会被检测为外挂吗？

### 结论（务实说法）

| 点 | 说明 |
|----|------|
| **机制** | 官方 GSI 通道，社区与第三方 overlay/HUD 长期使用 |
| **进程** | 不注入 `dota2.exe`，不修改游戏内存 |
| **网络** | 默认只监听 `127.0.0.1`，数据由游戏进程**主动发出** |
| **VAC** | VAC 主要针对注入/篡改客户端；纯 GSI 监听通常**不按外挂注入类处理** |
| **平台规则** | 仍须遵守 Steam/Dota 服务条款；若做成「自动操作/自动施法/辅助瞄准」则完全不同性质 |

**DoDoClaw 当前定位：教练建议 + 提醒 + 语音**，不代替键鼠、不自动点技能。

### 仍要注意

1. **不是法律/VAC 免死金牌**：Valve 政策可能变化；任何「承诺永不封号」都不严谨。  
2. **不要扩展成作弊工具**（自动买活、自动吃符、读取不该有的信息并辅助操作）。  
3. **观战/Demo** 下 GSI 字段可能不同，属预期行为。  
4. **第三方平台联赛** 若禁止外部软件，以赛事规则为准。  

社区推广文案可写：**「官方 GSI 读局，无注入」**，并附上本文档链接。

## 和 ASR / TTS / LLM 的关系

```
GSI 局势 ──┐
用户语音 ─ASR─► 文本 ──► LLM ──► 文本 ─TTS─► 播报
规则提醒 ───────────────────────────────► TTS
```

GSI 只增强「模型上下文」；ASR/TTS 可独立选 Step Plan 语音模型（`stepaudio-2.5-asr` / `stepaudio-2.5-tts`）。
